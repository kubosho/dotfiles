# japanese-proofreading

日本語の文書から、日本語の不自然な言い回しの形式を検出する。規則は固定の文字列照合で、同じ文章と同じ規則からは常に同じ指摘を返す。

## 使い方

```sh
node ~/.agents/skills/japanese-proofreading/detector/cli.ts <file>
```

`<file>` には検査する Markdown またはテキストのファイルを指定する。`-` を指定すると標準入力から読む。

## 出力

結果は JSON で標準出力に書く。

| 終了コード | `status` | 意味 |
| --- | --- | --- |
| 0 | `no-findings` | 指摘なし |
| 1 | `findings` | 指摘あり |
| 2 | `failed` | 検査失敗。ファイルがない、引数が誤っているなど。`error` に理由が入る |

`findings` の各要素は次の項目を持つ。

- `ruleId`、`pattern`：規則の ID と、対応する形式の見出し
- `line`、`column`：指摘箇所の位置。どちらも1始まりで、列は文字単位で数える
- `match`、`sentence`：指摘箇所の文字列と、それを含む文
- `reason`、`hint`：形式に当てはまる理由と、修正の方向
- `requiredInformation`：修正に必要だが、文章に書かれているとは限らない情報。文章や文脈から確かめられない場合は推測で補わず、不足している情報として報告する

`notice` は、未対応の形式があるため指摘がなくても文章全体に問題がないとは限らないことを示す。

## 検査しない範囲

- frontmatter、コードブロック、インラインコード、HTML コメント、`>` で始まる引用の行
- 同じ行で閉じている「」と『』の中。悪い例を引用していることが多く、書き手の地の文ではないため。「」で強調した語も検査しない

文は「。」「！」「？」「!」「?」と改行で区切る。1文を複数行に折り返していると、別々の文として判定する。

## 対応範囲

検出する形式ごとに規則を1つ用意している。どの規則も、列挙した目印の語がない文は検出しない。

| 形式 | 規則 ID | 検出するもの | 検出しないもの |
| --- | --- | --- | --- |
| 技術動詞の直訳で動作が特定できない | `literal-verb-translation` | 「割る」。「で割る」、「掛け」を含む計算の文、「割り当て」「役割」は除く | 「置く」「呼ぶ」「寄せる」など。語だけでは正しい用法と区別できない |
| 依頼が条件節に埋まり、主節が書き手の動作になる | `request-in-condition` | 「〜てもらえれば」「〜てくれたら」「〜ていただければ」などの後の主節に「が」「は」「も」がなく、動詞で終わる文 | 主節に主語がある文、「です」「だ」で終わる文、「〜してもらえると」の形 |
| 英語では薄れた比喩を、日本語の比喩語に置き換える | `calqued-metaphor` | 「骨格」。「骨格推定」「骨格筋」などの用語は除く | 「骨格」以外の比喩語 |
| 別分野の用語を説明に持ち込む | `foreign-field-term` | 「正本」、「限定が落ちる」、比喩、意味、イメージなど抽象的な主語の「立ち上がる」 | 列挙した語以外。「正本」を法律の意味で使う文も区別しない |
| 法律の規制や違反の語を評価の比喩に使う | `legal-metaphor` | 「過積載」「越権」 | 列挙した語以外。法律や規制を本来の意味で説明する文も区別しない |
| 動詞で書ける内容を漢語の名詞に変える | `nominalized-kango` | 「不存在」 | 「不存在」以外 |
| コードを主体としているのに人を指す語を使う | `person-word-for-code` | 「誰が」「誰から」のうち、同じ文にコードの識別子と、変換、返す、呼ぶなどのコードの動作がある文 | 識別子のない文 |
| 動作の仕様を程度を表す言い方に置き換える | `unspecified-behavior` | 「無言で」「黙って」「静かに」の後に、降りる、終了、返す、無視などのプログラムの動作が続く文 | 「降りる」だけの文。人の動作と区別できない |
| 異なる結果を汎用的な評価語で閉じる | `vague-evaluative-ending` | 文末の「効いた」「刺さる」「響く」「効果的です」など、「効いたのは」「効くのが」の構文 | 「有効だ」。技術文では有効化されている意味で使うことが多い。次の文で結果を書いている場合も指摘する |
| 文を「だから」やダッシュでつなぐ | `sentence-connection` | 「だから」で始まる文、文をつなぐダッシュ（`──`、`—`、`―`）。文書の種類によらず検出する | 文中の「だから」、「だからといって」 |

「情報量のない補足を付ける」は検出しない。「技術資産（すでにあるもの）」のような補足が言い換えかどうかは、語の意味から判断する必要がある。

## 評価データ

`detector/cases.json` に、文章（`text`）と期待する指摘（`expected`）を組にして記録している。問題例のほか、正常例、悪い例を引用した文章、修正に文章にない情報が必要な例を含む。期待する指摘は `ruleId` と `match` の組で照合する。

```sh
node dot_agents/skills/japanese-proofreading/detector/evaluate.ts
```

規則ごとの件数と、検出漏れ、誤検出を表示する。どちらかがあれば終了コード 1 で終わる。リポジトリのルートで `npm test` を実行すると、vitest が評価データも照合する。
